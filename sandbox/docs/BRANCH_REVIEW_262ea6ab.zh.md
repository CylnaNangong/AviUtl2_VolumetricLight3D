## 2. 代码审查

与该分支父提交 `b179e64` 的 v3.13 比较，除版本文字、说明、打包元数据外，光束计算的主要功能改动是 [`.obj2` L9015–L9047](https://github.com/CylnaNangong/AviUtl2_VolumetricLight3D/blob/cc99521dfcf7af9ce8b16cf53444d13f44f0b50e/Script/VolumetricLight3D.obj2#L9015-L9047)：当 `fill_mode != 1` 且 **不满足 `is_virtual_spot`** 时，`wboit_ka` 从 `0.24` 改为 `0.0`。就用户已确认的无摄像机光源条件，选择「光束质感 → 体积柔光」时会进入这一改动；「纯色实心」不使用该改动。

14 个 HLSL 源块与 v3.13 一致。`beamatlas` 原有分支在 `p26.w > 0.01` 时使用比例 alpha；否则输出 `p12.z` 常量 alpha（前提是该纹素有非零输出）。本次遮挡素材场景的最后一批 `beamatlas` 236 个 uniform 中，唯一的差异是第 107 项 `p26.w: 0.24 → 0.0`。其他参数、四边形几何和 `drawpoly` alpha 相同。

**适用范围不能简写成“任何聚光都不变”**。判断条件是 `use_cam_virtual_src`、相机跟随模式和 `ltype` 4/5 的组合；仅其中的虚拟聚光路径保持原值。详见第 5 节。

覆盖 Lua 执行、14 段 HLSL 的 CPU 转译、宿主 API 契约、语言包、可编译的桥接代码、遮挡和资源预算；**不包含 Windows 的插件 ABI / D3D11 GPU / 真机渲染**。完整机器可读结果为 `out/main-final.json`、`out/branch-final.json`（本地生成并被忽略）。

本次测试暴露并修正了沙箱本身的问题，不能把初始失败直接判为产品 bug：

1. 旧光栅器用 `1/255 ≈ 0.00392` 丢弃片元。项目逆向记录和归档 GPU 沙箱所采用的阈值约为 `0.001`，**并非官方 API 规范**。例如该场景 `tex.a = 3/255`、`drawpoly_alpha = 0.118806`，乘积约 `0.001398`：高于所假设的宿主阈值，却低于旧沙箱阈值，导致旧沙箱错误地渲染全黑。首次原样移植旧沙箱运行候选版得到 **69 PASS / 16 FAIL**：其中 2 项是硬编码 v3.13 的版本断言，另外 14 项受黑帧影响；它们不是 16 个已证实的产品缺陷。
2. 脚本超过 64 个切片会分批重建 `object` 图集；旧沙箱把最后一批纹理套用于全部四边形。现改为在每次 `drawpoly` 时保存当时图集，并用两种颜色的多次绘制进行回归测试。
3. 固定 alpha 编码下，alpha 表示覆盖而非光的强度。修正阈值及图集快照后、调整亮度断言之前，候选版结果为 **86 PASS / 4 FAIL**：两项雾、一项移动镜头和一项长度检查只看 alpha 差异。现在这些断言改用显式浮点假设模型的 RGB 信号，而不是仅为候选版降低阈值；改完后两版各 90 PASS。新增双边阈值、图集快照、两种 alpha 编码、整数十六进制等测试。版本检查也改为“版头和自身更新记录一致”，不再固定 v3.13。

旧的 `volume`/PNG 仍是 RGBA8 预览，不能可靠表达 HDR。另加的 `assumed_emission()` 提供两个**明确标记为假设**的浮点模型：等深度权重 WBOIT 近似，以及按记录顺序的预乘 over。它们都不包含真实的 3D 透视、宿主照明、深度权重或 GPU 行为，因此只能用于模型内的相对比较。

补充打包检查：目标 `packaging/build_au2pkg.py` 已构建并检查完整版（9 项，含插件、4 个语言包）和 ScriptOnly 版（7 项，不含插件）；两个 ZIP 校验通过、脚本内容一致、版本均为 v3.14。未在 AviUtl2 中安装这两个包。

## 4. 用用户素材进行的可复现模拟

将彩窗 JPEG 缩小至 **220×158**、人物透明 PNG 缩小至 **120×120**；前者放光源层 1，后者放前景层 3（`x=15,y=10,z=-200`），效果层 4。模拟画面 256×144、帧 0；`intensity=180`、`res_mode=2`、自动切片（此场景共 66 片、2 批）。下表是**等深度权重假设模型、黑底、未裁剪的 RGB 亮度代理均值**：

| 模拟场景 | v3.06 参考 | v3.13 | v3.14 | v3.14 / v3.06 |
| --- | ---: | ---: | ---: | ---: |
| 平行光，无遮挡 | 0.046414 | 0.043342 | 0.046388 | 0.9994 |
| 平行光，人物 2D 遮挡 | 0.025832 | 0.024258 | 0.026150 | 1.0123 |
| 人物遮挡 + 烟雾 70 | 0.018810 | 0.016953 | 0.019049 | 1.0127 |

同样的四组参数下，另一种 `over` 模型也出现接近旧版的趋势，但两种都不是宿主实际 WBOIT。素材输入是 8 位编码数据；上表不是线性光辐射值，也不是用户视频的亮度百分比。尤其不能据此断言真实画面差异必然小于 1%。

以人物遮挡场景为例：两版 42,942 个均有输出的图集纹素中，RGB 全部相同；候选版另有 21,644 个纹素有输出、v3.13 为零。这是**图集纹素数，不是最终屏幕像素数**。它说明在此场景下比例 alpha 的低值门确实会影响着色器输出，不能仅凭分支数字孪生断言低值门的贡献“约为零”。

该场景模型的平均覆盖率也从 v3.06 `0.002962`、v3.13 `0.007218` 变为 v3.14 `0.004163`；候选比 v3.13 小，但**并不等于** v3.06。统一灰底 `0.5` 时，三版模型输出均值依次为 `0.524351 / 0.520649 / 0.524069`。这说明黑底接近不自动意味着背景遮蔽完全相同。

| ---: | ---: | ---: | ---: | ---: |
| 1 | 0.00001125 | 0.00000030 | 0.00000126 | 0.112 |
| 5 | 0.00042913 | 0.00003162 | 0.00058087 | 1.354 |
| 10 | 0.00120189 | 0.00006171 | 0.00134803 | 1.122 |

### 4.2 配对消融：alpha 编码与低 alpha 门

根据用户后续确认的“无摄像机光源”，在相同素材和人物遮挡模拟场景中，对 v3.13 的 HLSL 做**临时副本**变异，分别切换比例/常量输出 alpha 和 HLSL 内的低 alpha 返回零门；不修改原脚本。各种反事实都保留其他 RGB 零值检查以及假设的宿主 `0.001` 片元丢弃门。因此“关 HLSL 门”并不等于关掉所有后续片元丢弃。以下为「发光强度」180 的等深度权重模型、黑底未裁剪光量代理：

| 反事实变体 | 输出 alpha | HLSL 低 alpha 门 | 模型光量 | 平均覆盖率 |
| --- | --- | --- | ---: | ---: |
| v3.13 原样 | 比例 | 开 | 0.024258 | 0.007218 |
| 只关 HLSL 门 | 比例 | 关 | 0.024706 | 0.007349 |
| 保留门，输出改常量 | 常量 | 开 | 0.024181 | 0.002541 |
| 同时改常量并关门 | 常量 | 关 | 0.026150 | 0.004163 |
| v3.14 候选 | 常量 | 关 | 0.026150 | 0.004163 |

“常量 + 门开”是在按 v3.13 的比例 alpha 执行门判断后，才把通过门的输出 alpha 改为常量；“常量 + 门关”同时绕过该门。候选与“常量 + 门关”在强度 **180、30、5** 的模拟下，图集逐字节、四边形几何及两种模型输出均一致；着色器参数中摄像机光源补偿模式均为 0。对照实验说明，在此模型和场景中，保持旧门时仅改输出 alpha 未使黑底光量回升，而两项同时改变才回升；低 alpha 门与编码有交互，不能把提升全部归因于“不透明度变小”。这个反事实仍受宿主阈值、投影和合成假设限制，**不能据此断定真机哪一项占主导，更不能把差值当成用户画面的百分比**。可复现脚本及命令见第 8 节。

## 5. 聚光和其他路径的边界

通过脚本已有 `VL3D_TEST_CAM_LIGHTS` 测试钩子注入模拟灯光，并非读取了真机 `CameraLight64`：

| 被测路径 | v3.13 `p26.w` → v3.14 | 沙箱观察 |
| --- | --- | --- |
| `src_layer=0`、跟随摄像机、虚拟聚光 `ltype=4` | `0 → 0` | 图集逐字节相同 |
| 同上，虚拟聚光 `ltype=5` | `0 → 0` | 图集逐字节相同 |
| `src_layer=0`、跟随摄像机、虚拟点光 `ltype=3` | `0.24 → 0` | 图集改变，属于预期修复范围 |
| **有图层光源** `src_layer=1`、跟随摄像机、灯光 `ltype=4` | **`0.24 → 0`** | 不满足 `use_cam_virtual_src`，图集确实改变 |

因此可以说测试到的**无图层光源的虚拟聚光**执行路径未改，不能说所有与聚光有关的配置均不受影响。真实聚光灯的动态边缘、年轮和阴影还要在 AviUtl2 中验证。另做的 `fill_mode=1` 纯色实心对照：两版 32 个四边形、`p26.w=0`，模拟帧一致；这仍不是实机验证。

## 6. 分支自带分析报告的具体问题

1. **消融开关没有使用。** [`analysis/beam_brightness_twin.py` L87–L104](https://github.com/CylnaNangong/AviUtl2_VolumetricLight3D/blob/cc99521dfcf7af9ce8b16cf53444d13f44f0b50e/analysis/beam_brightness_twin.py#L87-L104) 接收 `gate=True/False`，却始终无条件执行 `if out_a < min_a - 0.25/255`。固定同一种随机种子，`gate=True` 与 `gate=False` 返回完全一致；报告中“去掉地板门”的微小差别来自不配对的随机采样，不是有效消融。应让开关真正控制该分支，并使用相同随机样本；同时分别统计 HLSL 门和后续宿主片元门，避免关闭前者后又被后者丢弃而误判。
2. **M2 并非完整 WBOIT 合成。** [`additive_wboit()` L122–L128](https://github.com/CylnaNangong/AviUtl2_VolumetricLight3D/blob/cc99521dfcf7af9ce8b16cf53444d13f44f0b50e/analysis/beam_brightness_twin.py#L122-L128) 只累加深度加权 RGB，缺少报告所引用的 alpha 加权分母和 `Reveal`；无法独立验证背景 veil 或声称完整 WBOIT 与 M1 一致。M1 自身也只是归档 GPU 沙箱的 over 假设，不是实机 OIT 的证明。
3. 数字孪生用 `core_emit = min(1, W)` 和固定颜色剖面简化了实际 HLSL 中独立的 `w_core_acc`、`slab_gain`、`core_c`、遮挡与雾。因此 `0.91–0.96× → 0.95–1.00×`、veil 回到 v3.06、及“<1%”应标为**该模型特定条件的估计**，而非普遍的真实导出结论。
4. 当前候选把常量 alpha 放得接近假设的 `0.001` 丢弃阈值；纹理双线性采样、近零像素和相机运动可能影响边缘稳定性。静态 CPU 用例不能排除真实宿主中闪烁或条纹；应实际测试低强度与动态边缘。
