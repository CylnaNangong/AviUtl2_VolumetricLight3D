## 1. 本次联动的核心设计要点（防坑自查清单）

1. **跨脚本 `global` 传输已做成 100% 纯 7-bit ASCII Base64（`VL3DB64:...`）**：
   - 我们特意考虑到 `aviutl2.exe` 内部桥接 `global` 表时如果走了 `lua_tostring` / `lua_pushstring`（遇到 `\0` 截断 C 字符串），裸二进制包会在第 8 字节被截断！

3. **互不误遮挡**：

## 3. 推荐在 `AviUtl2 v2.1.16` 真机重点验证的 5 个场景

### 场景 A：基础光束照亮 + 光束外压暗（丁达尔微尘感）
- **Layer 1**：小尺寸明亮色块或彩绘玻璃窗（例如 `200×200`，放在 `Z = 600`）
- **Layer 3**：`体积光（3D）v3.16`（光源图层=`1`，方向朝镜头，开启日志输出）
- **Layer 4**：`雪（3D）v1.23`（展开「体积光联动」，默认 `受体积光照亮 = ON`；尝试把 `光束外与阴影压暗` 拉到 `80~100%`）
- **预期结果**：
  - 日志窗口打印 `雪（3D）v1.23 ... 体积光=ON(1:<受光粒子数>)`（**绝不应停留在 `WAIT`**，若出现 `WAIT` 说明 `global` 没收到包！）；
  - 穿过光束内部的雪花明显染上光束颜色并发出柔和前向散射光晕，光束外的雪花按设定比例压暗；彩绘玻璃左右不同色块下的雪花分别染上对应红/蓝/金色！

### 场景 B：真 3D 投射阴影（“被遮挡就不亮”，核心验收项！）
- 在场景 A 的 **Layer 2** 放入一个 **`.obj` / `.vrm` 3D 模型** 或 **2D 人物/方块遮挡物**（位于光源与镜头之间，例如 `Z = 250`），`体积光（3D）` 设为 `3D影のみ(物理遮光)` 或 `3D影＋前景マスク(推奨)`，并把光束调成斜向射过画面。
- **预期结果**：
  - 处于光源与遮挡物之间（上游）的雪花**依然明亮发光**；
  - 落入遮挡物后方斜向 3D 阴影柱内的雪花（哪怕在镜头画面上并没有被遮挡物挡住！）**立即熄灭不发光**！

### 场景 C：前景人物轮廓保护（`occ_mode = 2 / 3`）
- 2D 立绘或 VRM 角色放在 `Z = 100`，雪花分布在 `Z = -200 .. +500`。
- **预期结果**：飘在角色胸前（`Z < 100`）的受光雪花正常在角色衣服前闪亮，而在角色背后（`Z > 100`）的受光光晕不会穿透角色立绘产生漏光。

### 场景 D：停用 / 强度归零 / 子场景隔离
- 把 `体积光（3D）` 的 `强度` 拉到 `0` 或隐藏体积光对象，确认雪花受光**当帧立即消失、无残光**；
- 在 `Scene 1` 子场景里放一盏红光 `体积光（3D）`，确认主合成 `Scene 0` 里的 `雪（3D）` **完全不会串光变红**。

### 场景 E：多体积光叠加 + 摄像机控制 3D 聚光灯
- 同时开启两层不同颜色的 `体积光（3D）`（例如左暖金 + 右冰蓝），观察交汇处雪花的双色混合提亮；以及测试 `相机光源联动 = 跟随相机光源` 下的 3D 聚光灯圆锥照亮雪花。

## 4. 真机首轮实测反馈闭环记录：`3D光源雪测试` 雪花柔边变黑（WBOIT `Accum_w` 权重劫持）与逆光法线修复

首轮真机 `AviUtl2 v2.1.16` 实测结果：
- **2D 图层光源（彩绘玻璃教堂逆光）**：100% 完美通过！
- **3D 摄像机聚光灯（`光源=图层0` + 青色 3D 聚光灯从右上后方斜射左下前方）**：左下角光束区重叠的雪花粒子外围出现了**一圈明显的暗黑色柔边圆环**（实测像素截面：青色光束背景 `(0, 145, 145)` 在粒子柔边 `r ≈ 8..11 px` 处骤降至 `(12, 59, 59)`，另一颗从 `(0, 46, 46)` 跌至 `(4, 20, 20)`）。

### 数学根因（双重耦合机制）
1. **`Shader #118` WBOIT `Accum_w` 权重劫持（黑边圆环主因）**：
   - 3D 聚光灯体积光切片采用极低 `out_a_sp = 4/255` × `poly_alpha = 0.064125`（单切片 `a118 ≈ 0.001006`，整条光束累积 `1 - Reveal ≈ 0.05`），其直通色比值高达 $C_{\text{beam}} = \text{Accum}_{\text{rgb}} / \text{Accum}_w \approx 6\sim 13$（HDR 发光态），在暗黑背景 `(0,0,0)` 上最终解析为 `(1 - Reveal) * C_beam ≈ 0.57`。
   - 当前景未受光雪花以默认 `blend = "none"` 进入同一 `Shader #118` WBOIT 累加器时，其高斯柔边外裙（`a_snow ≈ 0.01..0.08`）乘上近景指数深度权重 $w(z_{\text{near}}) \gg w(z_{\text{beam}})$，瞬间占满像素的 `Accum_w` 分母，却只贡献暗淡的 `unlit ≈ 0.25` 灰白值，且 `1 - Reveal` 仅从 `0.05` 微增至 `0.09`——导致原本明亮的青色光束平均值被瞬间稀释近 60%，形成肉眼可见的黑圈！
2. **宿主 3D 光照 `H_host(wp, N)` 逆光法线归零**：
   - 5 元顶点 `{x,y,z,u,v}` 的默认广告牌法线朝向镜头 `-f`，当 3D 聚光灯从粒子后方逆光射向镜头时 $\mathbf{N}\cdot\mathbf{L} < 0 \Rightarrow \max(0,\mathbf{N}\cdot\mathbf{L}) = 0$，宿主硬件着色器将粒子受光项清零（若聚光灯 `明るさ >= 100%` 即 `unlit = 0` 更会完全变黑）。

### 二轮真机反馈（`测试沙箱2.aup2` 开启「视角切换」`camera_mode == 2`）与最终根治方案（`108/108` 沙箱全绿）

在首轮尝试 `obj.setoption("blend", "add")` 后，真机在 `测试沙箱2.aup2`（开启右上角蓝色准星「视角切换」编辑自由相机 `camera_mode == 2`）复测发现：
- **好消息**：光束圆锥内部的 8 颗青色受光雪花已 100% 正常发光且外围零黑圈（如 `(500,263)` 从背景 `(66,179,179)` 单调升至 `(98,253,253)`）；
- **残余问题**：处于聚光灯圆锥外侧、但在编辑相机视线上投影叠在青色光束前方的前景未受光雪花（如 `(568,334)` 与残影 `(458,264)`）**依然带有明显暗圈/黑洞**（青色 `(0,137,137)` 在雪花柔边裙摆处跌至 `(2,44,44)`，跌幅 `-93/255`）。

#### 为什么 `2216fa9` 的 `blend = "add"` 没能绕过前景黑圈？
逐像素拟合真机截图确认了两条关键宿主硬件事实（也同步修正进了 `sandbox/vl3dsb/compositor3d.py`）：
1. **在 `AviUtl2 v2.1.16` 3D 摄像机控制通道（`カメラ制御の対象` 开启）下，对象脚本内调用 `obj.setoption("blend", "add")` 依然流经 `Shader #118`（`0x1404404b0`）WBOIT 累加器**，并不会切换为硬件 `ONE+ONE` 直加！因此前景暗雪花的高斯外裙（`tex.a ≈ 0.004..0.08`）乘上近景权重 $w(z_{\text{snow}}) = e^{-z_{\text{snow}}/550} \gg w(z_{\text{beam}})$ 后仍然会劫持 `Accum_w`。
2. **开启「视角切换」（`camera_mode == 2` 编辑自由相机）时，`obj.getoption("camera_param")` 仍返回时间轴相机**：`Snow3D` 没有加载 `.aux2` 插件，若不从 `VL3DLF` 获取实时渲染相机基底，广告牌朝向、深度排序与视线重叠判定都会停留在旧时间轴视角。

#### 最终合入的双通道比率不变 WBOIT + 实时相机同步方案（`+0` 额外缓存像素）
1. **`VL3DLF\3\0` 扩展至 `320` 字节头（`flags` `bit 9 = 512` `has_ext_cam`）**：
   - 在 `f32[56..69]` 发布 `VolumetricLight3D` 当前帧真实渲染相机基底（`cam_x..z, f_x..z, r_x..z, d_x..z, focal_d`）以及宿主 3D 光照背光上界 `host_unlit_max`（`unlit + amb`）；`Snow3D` 向后兼容 `264B / 320B` 双长度包。
2. **`camera_mode == 2` 编辑自由相机实时同步（`SNOW_LF.resolve_view_cam`）**：
   - 当处于「视角切换」模式且 `VL3D` 持有精确编辑相机时，`Snow3D` 保持雪盒中心锚定在时间轴注视点（方便围绕角色和光束自由旋转观察），同时将粒子广告牌正对基底 `(r, u)`、深度排序、Band 2 前景遮罩以及视线后方光束探测实时同步到编辑相机！
3. **双通道比率不变 WBOIT 量化（`SNOW_LF.probe_ray_behind` + `ps_snow_shape_tint` `wboit={1,5,0,0}`）**：
   - 对每颗存活粒子沿实时相机射线检测其后方是否穿过活动体积光束并估算深度权重比 $\rho_w = \operatorname{clamp}(e^{(z_{\text{beam}}-z_{\text{snow}})/550}, 1, 8)$；
   - **不与光束重叠的粒子**走原生的 `Pass 1`（暗空与不透明背景上与原版 100% 一致）；
   - **与光束重叠的粒子**走 `Pass 1b`（白核）+ `Pass 2`（受光彩色光晕），在 `ps_snow_shape_tint` 中输出比率不变最小量化令牌 $\text{out\_a} = \lfloor 5a + 0.5 \rfloor / 255$：
     - 外圈高斯柔边（$a < 0.10$）满足 $r_4.w < 0.001$，直接触发 `Shader #118` 硬件 `discard`，**从物理上根绝柔边裙摆写入 `Accum_w`**；
     - 核内有效像素保持 $\text{tex.rgb} / \text{tex.a} \equiv \text{const}$，并按 $1/\rho_w$ 缩放 `poly_alpha` 抵消前景深度权重膨胀；当聚光灯 `明るさ >= 100%` 且零环境光（`host_unlit < 0.025`）或粒子处于极淡生灭残影（`a_wb < 0.055`）时自动剔除，彻底杜绝黑洞。
   - 260 粒子全画幅压力回归实测：旧路径光束区最深暗化 `-38.2/255`（968 像素变暗），新路径在时间轴相机与 `camera_mode == 2` 编辑相机下均为 **`min_dG = 0.00/255`（0 像素变暗）**！

## 6. 第三轮真机截图回归：`image-7.png` OFF / `image-8.png` ON 后仍有少量黑圈（本次补丁）

感谢新的并排截图。图 2（体积光联动开启）相较图 1 已明显改善，但逐像素比对确认仍有少数大型雪粒子在青色光束视线上形成黑边/暗圆。本次不再把问题归因于 `"add"` 混合或旧的深度比参数：新的根因是旧 `probe_ray_behind` 的**光束漏检**。

- 旧探测沿相机射线仅检查有限个光源轴向位置，并把光束轴向距离近似成屏幕深度；它没有在每个候选位置同时确认实际束锥/有限长度内辐射、3D/2D 投影阴影深度以及相机前景 holdout。因此，个别画面上确实压在可见光束上的未受光雪粒被误判为光束外，仍按普通半透明卡片送入 `Shader #118` WBOIT，重新稀释体积光。
- 受光粒子另外有一条分流边界：微弱受光粒子可能被 glow 稳定阈值淘汰，但之前仍保留灰色 base pass，形成看似黑圈/灰圈的无配套底片。

### 此次修正
1. `probe_ray_behind` 现在求相机射线与每个发射器有效空间包围区及光程区间的交集，轴向采用 9 个中点并补充圆锥极值/最近距离点；每个候选点都检查实际 Spot 锥与射程、Band 0 辐射是否有效、Band 1（3D/2D）遮挡深度是否仍可见，以及 Band 2 相机前景 holdout 是否挡住该束光。仅当**真实有效的可见光束**出现在粒子前方且与屏幕粒径范围重叠时，才将该未受光粒子从 WBOIT 剔除；离开光束投影的雪粒仍照常绘制。
2. 调整像素覆盖半径为约 `0.85 × 粒子半径 + 4` 场景单位，减少仅因大范围包围采样而误抑制相邻、实际不相交的雪粒。
3. WBOIT base pass 仅绘制仍通过稳定受光阈值的粒子；被淘汰的微弱受光粒子同步撤销受光标记，不会只留下灰色底片。
4. 沙箱 compositor 新增基于真机像素拟合的 `wboit_hw118` 回归模式（近景深度强优先 + 非归一化纹理 RGB）；保留此前便于比较的标准 OIT 模式。

### 回归结果
- 新增断言覆盖：光束正前方未受光粒子被抑制、明确离开束锥视线的未受光粒子照常渲染、斜向光束后方未受光粒子被抑制，以及弱受光不留下孤立 base。
- 在“光束斜向穿过雪盒并由 3D 模型投影遮挡”的 `394` 粒子压力复现中，旧路径在 `175,396` 个青色光束像素上最深暗化 **`-55.8/255`**（`30,708` 个像素低于 `-5/255`）；新路径 **`min_dG = 0.00/255`，变暗像素 `0`**，且可见受光雪粒子峰值增亮 `+190.2/255`。
- `.venv/bin/python sandbox/run_checks.py`：**108 PASS / 0 FAIL / 0 SKIP / 0 WARN**。
