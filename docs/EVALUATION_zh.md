## 2. 评估方法与环境

评估环境为 Linux x64 容器（2 核 / 3.8 GB / 无 GPU / 无 Vulkan），**刻意**选择了比项目自带沙箱更严苛的条件：

1. **全量精读**：主脚本全部 9,553 行、C++ 全部源文件、SDK 头、ini/打包/语言包逐行阅读（重点：Win32 FFI 层、`.text` 特征码扫描、`ReadProcessMemory` 探针、摄像机光源数组解析、光栅化器、WBOIT/聚光灯补偿数学、AutoBlendLight 集成、重入保护）。
2. **宿主反编译逻辑的替代验证**：无官方 `aviutl2.exe`（版权物，仓库正确地未包含），采用三条替代路径核验逆向层：
   - 用 g++ 从源码构建 Linux 版测试库（`process_vm_readv` 等价实现 + mmap 合成宿主），运行其**内置的 33 项自测**——其中包括以真实 `mmap`+`mprotect(PROT_NONE)` 模拟宿主、验证特征码扫描命中、白名单门控与「读保护页绝不 SIGSEGV」；
   - 与独立第三方（`nove-nove/aviutl2-vrm-toolkit`）内置的官方 SDK 头做**结构 diff**；
   - 对 `VL3DBridge.aux2` 做 PE 导入/导出表审计，比对 `.ini` 中指纹字段的自洽性（`0x6ADC1302` = 2026-10-24T02:08:02 UTC，与宣称的 v2.1.15 发布日期 2026-10-24 吻合；`0x005F5000` ≈ 5.96 MiB 的 SizeOfImage 合理；插件自身 PE 时间戳 2026-10-24T09:11:58 UTC，晚于宿主 7 小时，时间线自洽）。
3. **沙箱测试**：仓库自带沙箱强依赖 Vulkan，本环境不可用（且 GitHub release 资产域、SwiftShader 预编译渠道均被网络策略封锁，构建 SwiftShader+Vulkan-Loader 软件栈超出时间预算）。**谨慎评估后**的处理方式：
   - 通读沙箱全部核心代码（`aviutl2_sandbox.py` 1,589 行 / `sandbox_v2_fidelity.py` 1,138 行 / `run_v306_checks.py`），确认其无危险行为（纯本地渲染与断言，无网络/无系统修改）；
   - 沙箱预编译 `lib_linux/*.so` 经符号表比对与源码构建版一致（差异仅为 GCC 版本产生的 STL 模板符号），但因依赖 GLIBC 2.38 无法在本机加载 → **用仓库源码现场构建的同名库替换后使用**（顺带完成了「预编译产物 ↔ 源码」的一致性验证）；
   - 为绕开无 GPU 限制，编写了 numpy CPU 后端垫片（`evaluation/cpu_gpu_shim.py`：多边形管线为精确实现，`ps_*` 全屏 pass 为恒等近似），使完整 LuaJIT 脚本可以在纯 CPU 上端到端执行。**局限性已明确**：像素着色器级别的视觉效果（光束着色、WBOIT 合成）不在验证范围内，但 Lua 侧全部控制流、缓冲/缓存生命周期、调用序列、CPU 光栅化、原生桥接与回退链均可验证。

## 3. 架构评估

### 3.1 优点

- **分层与回退设计成熟**。Lua 主脚本对每一层能力（插件存在性、`ffi.os`、`ffi.arch`、各 API 函数存在性、探针命中）都做了显式分级，`pcall` 包裹达 **174 处**；任何一层缺失都有定义良好的降级路径（本次实测：无插件纯 Lua、有插件 SDK 模式、原生 C-API 模式三条链路全部跑通）。
- **状态管理认真**。`_VL_PERSIST` 持久化缓存、`VL_BF` 帧状态机（prepare→capture→geometry→mip→occlusion→render 六阶段）、**同层/跨层重入保护**（快照-恢复 `VL_BF`/`P`，嵌套错误不污染外层缓存）——这是多实例共存的关键，实现正确。
- **FFI 无污染设计**。Lua 侧不向 `ffi.cdef` 添加任何可能与其他插件冲突的定义，而是手工解析 kernel32 PE 导出表拿到 `GetProcAddress` 再以匿名函数指针调用；PE 解析全程边界检查（`e_lfanew` 限幅、导出表 RVA 越界拒绝、名称未终止安全返回）。这套「零 cdef 污染」方案在共享 LuaJIT VM 的宿主里是正确且少见的工程决策。
- **D3D11 CS 管线有完整的上下文卫生**。`ScopedCsContextGuard` 保存/恢复宿主的 CS/SRV/UAV/CB 状态，`static_assert` 锁定 `EDIT_HANDLE::get_direct3d_device == 0xD8` 等 SDK ABI 偏移；HLSL 着色器带 `VL3D_VULKAN_TEST` 宏以支持沙箱的 Vulkan/SPIR-V 交叉验证（`spv_cache/` 内含 78 个预编译产物）。
- **缓存预算纪律**。所有中间缓冲以 `cache:vl3d/*` 命名并逐帧核算，帧末收缩到 1×1 释放；本次实测脚本自报峰值（871,587 dots）与沙箱侧独立统计**逐位一致**，证明其内部核算是真实的而非纸面声明。

### 3.2 批评

- **巨石单文件**。9,553 行 Lua + 14 个着色器在一个 `.obj2` 里，加上大量单字母/缩写局部变量与日文注释，人类维护门槛极高（历史上由 AI 协作迭代，changelog 密度佐证）。AviUtl2 的 `.obj2` 格式约束下没有完全的拆分自由，但纯计算函数（mesh loader、rasterizer、AB.*）本可拆为 `require` 的子模块（若宿主支持）。
- **部分函数过长**（如 `vl_bf_occlusion` 约 480 行、`AB.run_foreground_blend` 约 570 行），圈复杂度高，回归成本大——作者用沙箱回归测试补偿了这一点，方法论是对的。
- **`_G` 上有 27 处写入**，其中多数是测试钩子（`_G.VL3D_TEST_*`、`_G._VL3D_RESOLVE_LIVE_LAYER`），设计上有意为之，但建议在文档中列出全部全局名以避免与他脚本冲突（实测未与常见命名冲突）。

## 4. 逆向工程层评估（重点）

### 4.1 实现内容（已逐行核读）

| 探针 | Lua 侧 | C++ 侧 |
| :--- | :--- | :--- |
| Lua 场景上下文定位 | 扫描 `.text` 段特征码 `48 8B 05 disp32 / 48 8B 90 88 00 00 00`（mov rax,[rip+disp]; mov rdx,[rax+0x88]）自动提取全局变量地址；0 命中时回退已知 RVA（v2.1.15: `0x5901A8` / v2.1.14: `0x58AAB8`） | 同一特征码扫描（无 RVA 回退），命中才置 `sig_scene_ok` |
| 场景/层/对象结构遍历 | `lctx+0x88`→rctx→`+0x00` 场景指针、`+0x0C` 当前帧、层向量 `+0x08/+0x10`、层元数据 `+0x20`（隐藏位 `+0x10`）、对象向量二分查找（与宿主 `0x140030740` 同构）、效果链 `+0x18/+0x20`、效果名宽字符串 `+0x40`、`モデルファイル` 路径 SSO 判定（`+0xB8/+0xC0/+0xA8`） | SDK 路径优先，RPM 路径同套偏移 |

| 编辑视角相机（绿相机） | 第二特征码（31 字节，含 `4C 8B 80 off_w / 49 81 C0 off_c / EB 07 / 4C 8D 87`）动态提取全局地址与两个成员偏移，经 `VirtualQuery` 可读性检查后读取 14 个 float | 同构 + `VirtualQuery` 等价 |
| 未保存工程兜底 | `.aup2` 文件解析（UTF-16/多字节码页自适应、虚拟文件注入测试钩子） | — |

### 4.2 安全与健壮性核验结论

1. **只读承诺成立**：源码审计（Lua 与 C++ 均无 `WriteProcessMemory`/`VirtualProtectEx`/`CreateRemoteThread` 等）与二进制导入表审计（`VL3DBridge.aux2` 仅导入 KERNEL32 43 项 + msvcrt 46 项，全部为读/文件/同步类）双向印证；自测代码内建 `write_attempts == 0` 断言。
2. **崩溃安全成立**：所有探针读均经 `ReadProcessMemory`（内核态拷贝，遇 `PAGE_NOACCESS/PAGE_GUARD` 优雅失败）或 `VirtualQuery` 预检；内置自测含真实 `PROT_NONE` 页读取不 SIGSEGV 的用例（本次构建后实测通过）。宽字符串读取按 4KB 页边界分块，避免跨页失败。
3. **降级门控成立**：`strict_whitelist_only=1` 时仅 SHA-256/PE 指纹命中才启用探针；默认混合模式下「白名单 **或** 特征码命中」才放行，未知二进制直接降级 `SDK_ONLY_SAFE_DEGRADED`——自测覆盖了该逻辑（`strict_whitelist_blocks`、`sig_allows_rpm` 两用例）。
4. **数值域校验充分**：光源类型限 0–5、RGB 限 0–100、层数 ≤4096、对象区间一致性等，误读宿主内存时大概率得到「无命中」而非错误行为。

### 4.3 风险与保留意见（无法在本环境闭环的部分）

- **偏移正确性无法对官方二进制实测**（`0x88/0xD0/0x98/0xA0`、`CameraLight64` 布局、两个特征码在真实 `aviutl2.exe` 中的唯一性/多义性）。本次只能验证：① 源码内部 Lua↔C++ 双实现偏移一致；② 特征码语义与 x64 编码学正确；③ 自测的合成宿主上行为正确；④ `.ini` 指纹与宣称版本日期自洽。**这是本报告最大的不确定性来源**，与 README 第 6 节的自我披露一致（作者将此类依赖明确标注为「存在局部失效风险」，诚实）。
- 特征码扫描会一次性读取整个 `.text`（约 6 MB）做字节匹配，每进程一次并缓存，性能影响可接受；但未来宿主若加壳/混淆/重排，扫描将失效——届时依赖 `.aup2` 文件解析兜底，功能退化路径已在文档说明。

### 5.3 唯一「FAIL」的定性：双光栅器容差

`E3` 断言 Lua 与 C++ 两套独立 CPU 光栅器输出的阴影图逐字节一致（阈值 maxdiff≤4），实测 **maxdiff=15**。深入分析（`evaluation/analyze_shmap_diff.py`）：

- 覆盖率（alpha）**0 处不一致**（13,197 个覆盖像素）；
- 深度仅 **5 个像素**有差异（0.038%），其中 4 个为 24 位深度编码的末位舍入（<1/2²⁴），**1 个像素**存在 15/255（R 通道）的真实深度差；
- 该像素位于笼体细线边缘——两套光栅器（Lua：double 精度 + 自有边函数；C++：float + 大三角形子块切分 `kLargeBboxThreshold`）在同亚像素位置选取了不同的「最近三角形」。

**定性：独立实现间的正常填充规则容差，非逻辑缺陷**。阴影最终经半影柔化（`occ_soft` 默认 8px 高斯）与 24-bit 深度重建，1 像素 6% 深度差在视觉上不可分辨。结论：两套实现相互验证了对方的正确性（覆盖率 100% 一致本身就是极强的信号）。建议作者将 E3 类断言的阈值放宽至「覆盖率 0 不一致 + 深度差像素占比 <0.1%」。

### 5.4 CPU 垫片的已知局限（影响范围声明）

`ps_*` 全屏像素着色器以恒等近似执行 → **光束的最终视觉着色、WBOIT 深度权重合成、聚光灯余弦补偿等像素级效果未被本环境验证**。这部分正确性此前由作者在真实 Vulkan GPU 沙箱（`spv_cache/` 78 个预编译 SPIR-V + glslang）与实机上验证过（changelog 中大量以 RMSE 计量的像素级回归记录，如「Shader #118 消灯画像 RMSE=0.89/255 検証済」）。本次验证覆盖的是：全部 Lua 控制流、缓冲生命周期、缓存预算、回退链、双光栅器、原生桥接、参数矩阵——即「程序对不对」，而非「画面美不美」。

## 9. 总评

这个项目最罕见的品质是**「激进的功能」与「保守的失败模式」并存**：它为了实现完整的三维光影联动，做了同类脚本几乎无人尝试的事——逆向宿主内存结构、手写 CPU 光栅化器、在官方 SDK 边缘调用 D3D11 计算着色器；但每一步都配套了多层验证（PE 指纹/特征码/数值域校验）、多层回退（GPU→C++→Lua、SDK→探针→文件解析）和只读不可崩溃的硬约束。本次评估在无 Windows、无 GPU、无宿主本体的条件下，把「能验证的部分」验证到了极限：**源码可信（可构建、零警告、自测全过）、二进制无害（导入表审计）、行为可信（CPU 端到端 20 项检查、参数矩阵零错误、缓存预算与自报逐位一致）、声明属实（量化声明全部核对）**。剩余的不确定性（逆向偏移对真实宿主的命中率、GPU 像素级效果）属于客观条件限制，且作者在 README 中的披露与之相符。

对普通用户的建议：放心安装 `Script`（纯官方 API，零风险）；生产环境可加装 `Plugin` 并开启 `strict_whitelist_only=1`；宿主升级 AviUtl2 后若 HUD 探针字段缺失，属预期内的局部降级，核心体积光功能不受影响。

对作者的建议：优先处理 §7 的 #2/#3（白名单口径与管辖范围，两个纯文档/一行代码级修改），并将本次交付的 CPU 沙箱垫片（`evaluation/cpu_gpu_shim.py`）纳入常规 CI——它让无 GPU 环境也能跑结构回归，与你的 Vulkan 保真沙箱互补。
