## 0. TL;DR（结论）

| 问题 | 答案 |
| :-- | :-- |
| **哪里出了问题** | `v3.08`（commit `a86c0ae`）给**非聚光源路径**（2D 图层光源 / 点光源 / 平行光，即 README 演示工程所用路径）引入的「比例 Alpha 编码」：Lua 侧 `wboit_ka = 0.24` + 着色器内 `ka_eff = max(0.24, min_a*2.4/core_emit)`、`out_a = round(emit·ka_eff·255)/255` 与 `out_a < min_a-0.25/255 → discard` 门。它使切片栈总不透明度（veil）膨胀到 v3.06 常量 alpha 令牌的 **约 2 倍**（孪生实测 `0.198` vs `0.096`），在宿主 OIT 合成中变成「深处切片自衰减 + 光束下背景被额外遮蔽」，光束整体暗 **4%～9%**（亮背景上更明显）。v3.09～v3.13 均未触及非聚光路径，故一直保留到最新导出。 |
| **当初为什么引入** | 为根治**聚光锥**在宿主 WBOIT 深度权重 `w(z)` 下的「年轮锯齿环」与「灰色烟雾 veil」：比例 Alpha 让全切片 Straight 色比 `r4.rgb / r4.w` 恒定，从而深度权重无关（见 v3.08 / v3.09 changelog）。该需求真实存在，但**只针对聚光锥**；聚光路径自 `v3.12` 起已改回「常量 alpha + 色比颜色」（`wboit_ka = 0`、`min_opt_a = 4/255`），非聚光路径却仍留在 v3.08 方案上 —— 属于「修复 A 路径的副作用遗留在 B 路径」。 |
| **怎么修正** | 已随本分支 **v3.14** 提交：非聚光路径 `wboit_ka = 0.24 → 0.0`（着色器既有 `if (p26.w > 0.01)` 门自动回落到 `out_a = p12.z` 常量令牌），与 v3.06 及 v3.12+ 聚光路径对齐。孪生验证亮度比 `0.91~0.96× → 0.95~1.00×`，veil 回到 v3.06 水平；不影响任何聚光修复。回退 = 一行改回 `0.24`。 |
| **次要因素（非 bug）** | `v3.07` 的逐像素宿主照明逆补偿含 `saturate(1/H)` 截断：若工程里摄像机控制「发光度」> 100% 或存在环境光/多灯（`H > 1`），v3.06 会额外乘 `H` 而新版锁定设计亮度，看起来再暗 `1/H`。属预期行为；如需旧观感把发光度调回 100% 或按比例上调「强度」。 |

README 演示动图 / 对比图源工程 = **v3.06**（commit `b79f103`，2026-10-24，Initial release）；
最新导出 = **v3.13 + 改名提交**（HEAD `b179e64`）。其间改动：

| `3b7fa1f` | v3.13 | HUD 近裁剪面投影、导出自动隐藏 HUD | 无 |

**着色器块级 diff 证据**（v3.06 ↔ HEAD，14 个 HLSL 块逐一比对）：仅 `beamatlas`（516 行非注释差异）
与 `ps_vl_white`（24 行，仅聚光虚拟光阑形状，`shape_mode=0` 时字节不变）发生变化；
`ps_vl_pool / ps_vl_prep / ps_vl_pack / ps_vl_blur / occ_* / ab_*` 等光源提取与 mip 链路 **0 差异**。
⇒ 亮度回归只可能出在 `beamatlas` 输出级或 Lua 增益链，与光源阈值提取、 mip、遮挡链路无关。

Lua 增益链核对：`k_gain_base = (intensity/100)*0.155/L_char`、`k_gain_gpu = k_gain_base*(base_alpha/poly_alpha)*1.05*cam_comp`
在各版本**形式完全一致**，且 `poly_alpha*k_gain_gpu` 为版本不变量（设计守恒）——即「脚本意图的每切片屏幕增量」
`c_i = poly_alpha*q_i` 在各版本间相同。**因此亮度差只能来自输出级的 (q, alpha) 编码与宿主合成对 alpha 的响应。**

## 2. 数字孪生（CPU 沙箱模拟）

`analysis/beam_brightness_twin.py`（无需 GPU / AviUtl2）复刻：

1. **Lua 增益链**（逐版本分支：v3.06 常量 `poly_alpha=0.27, min_opt_a=1/255`；v3.08+ 自适应 + `wboit_ka`）；
2. **`beamatlas` 输出级**：v3.06 = 三通道独立抖动 + 常量 alpha 令牌；v3.08+ = 单色 IG 抖动 + 比例 Alpha +
   `min_a` 地板门（v3.12 给聚光的相干存活分支在非聚光分支**不存在**）；
3. **宿主 Shader #118**：`a118 = tex.a*poly_alpha <= 0.001 → discard`；`r4.rgb = tex.rgb*poly_alpha*H`
   （`H = unlit_mul + amb + cl_rgb*Cone*Atten*N·L`，v3.07 changelog 记载的宿主照明模型）；
4. **宿主合成**：M1 = 仓库自带 GPU 沙箱 `aviutl2_sandbox.py` 的 `none_oit` 管线（深度序 premultiplied over）；
   M2 = changelog 记载的 WBOIT 深度权重 `w(z)=exp(-0.085z)` 加权和（仅切片间权重，版本比值与归一化无关）。

场景：96 切片、`L_tot=1400`、指数衰减剖面、源色通道比 (1, 0.82, 0.64)（彩绘玻璃暖色）、`intensity=150`。

### 2.3 消融（peak_c=0.012，分离各机制）

* **`min_a` 地板门（discard）在演示亮度下贡献 ≈ 0**（它只在极暗光束下咬合：M2 模型 peak_c=0.004 时比值 0.84）；

  每切片 `a*poly_alpha` 从 v3.06 的 `0.00106` 抬到 `0.0023~0.0029`），即 veil 膨胀 → 自衰减 + 背景遮蔽。

### 2.4 宿主照明 H 扫描（v3.07 机制，独立于上述回归）

⇒ 若旧工程「发光度」> 100%（或环境光/多灯使 `H>1`），还会叠加一个 `1/H` 的变暗 —— 这是 v3.07 的预期行为
（v3.06 的「发光度越高光束越暗/越亮反向响应」bug 的反面），不是本次回归的一部分。

## 3. 机制解释（为什么比例 Alpha 会变暗）

宿主对每个通过 `0.001` alpha 测试的切片做 `r4.rgb = q*poly_alpha*H`、`r4.w = a*poly_alpha` 的合成。
脚本侧守恒量是**颜色** `q`（`poly_alpha*q = c_i` 与版本无关），而 **alpha 只通过合成器影响结果**：

* v3.06：`a ≡ 1/255` ⇒ 每切片不透明度 `poly_alpha/255 = 0.00106`，96 切片栈 veil ≈ `0.096`；
* v3.08+：`a = emit*ka_eff`，`ka_eff ≥ 0.24` 且暗切片被 `min_a*2.4/core_emit` 再抬 2~4 倍 ⇒
  栈 veil ≈ `0.20~0.26`。多出的不透明度 (a) 在深度序合成中**逐切片衰减后到的光**、(b) 按 `bg*(1-veil)`
  **额外压暗光束下的背景** —— 两者都表现为「光束变暗」，而加法项 `Σ w*q*poly_alpha` 本身并未变。

比例 Alpha 当初要解决的是另一件事：宿主 WBOIT 的最终颜色 ≈ `Σ w·a·C / Σ w·a`（`C = r4.rgb/r4.w` 为 Straight 色比）。
常量 alpha 时 `C_i ∝ q_i` 逐切片变化，深度权重会把颜色往暗切片「稀释」→ 聚光锥上年轮环 + 灰色烟雾。
比例 Alpha 令 `C ≡ 1/ka` 恒定从而根治 —— **但该伪影只出现在聚光锥的锐利半影带**；v3.12 已用
「常量 alpha + 色比颜色 + 低亮度相干存活」在聚光路径上同时解决了环与 veil，非聚光路径却从未回退。

## 5. 局限与诚实声明

* 两个 mp4 无法在本沙箱下载，未能做像素级视频比对；孪生的宿主合成模型 M1 取自仓库自带 GPU 沙箱
  （`aviutl2_sandbox.py` 的 `none_oit` 管线，项目方在 v2.90～v3.06 验证中使用），M2 取自 changelog 文字描述，
  真实宿主可能介于两者之间 —— 但「veil 膨胀 ⇒ 变暗」在两种模型下定性一致，M1 定量、M2 保守；
* 孪生为单射线列模型（不含 2D/3D 遮挡、烟雾 fbm、AutoBlendLight），用于版本间**比值**归因足够；
* 若你的工程「发光度」> 100%，请同时参考 §2.4 的 `1/H` 预期差。
